# Замысел

**scorm-inspector** — веб-приложение для тестирования, отладки, воспроизведения и рецензирования SCORM-курсов.

Изначальная мотивация: приёмка и диагностика учебных SCORM-пакетов сейчас ручная и неглубокая. Инструмент должен:

1. Проверять пакет до загрузки в LMS (manifest, файлы, runtime-вызовы).
2. Помогать находить причины «курс не финиширует / не ставится оценка».
3. Давать минимальный воспроизводимый кейс для бага.
4. Формировать отчёт для рецензента; поэкранные комментарии для SME и заказчиков.

## Целевой пользователь

- **Заказчик/методист** — загружает пакет, получает отчёт о проверках.
- **SME / рецензент** — смотрит курс, оставляет поэкранные комментарии.
- **Администратор** — управляет пользователями и пакетами.

Инструмент публичный (для внешних пользователей), self-hosted: сначала запускается локально у владельца, после стабилизации — Docker Compose на VPS.

## Ключевые решения (аналитическая сессия 2026-09-06)

- **Форма**: веб-приложение (интерфейс в браузере), движок проверок + плеер + панель комментариев.
- **Стек**: TypeScript end-to-end — Next.js + PostgreSQL (в docker-compose, локально бесплатно). Правило «новый код — Go» из брифинга владельцем для этого проекта явно отменено: выбран идеальный стек под задачи (плеер — по сути JS в iframe).
- **SCORM 2004 only** (3rd/4th ed.) на старте; SCORM 1.2 — позже.
- **Аккаунты**: self-hosted, пакеты и комментарии сохраняются между сессиями (Postgres).
- **Экспорт**: xlsx/pdf — находки проверок + комментарии.
- **UI**: минимальный, «главное — работает».
- **Репозиторий публичный**; реальные учебные курсы не заливать — только синтетические фикстуры (чужой IP и возможные личные данные).

## Архитектура (стартовая)

```
Browser (Next.js, TS)
 ├─ /upload     — загрузка пакета
 ├─ /packages   — список пакетов/проектов
 ├─ /report/:id — отчёт по проверкам
 ├─ /play/:id   — плеер: iframe с курсом + панель комментариев
 └─ /export/:id — скачивание xlsx/pdf

Next.js API routes (TS)
 ├─ POST /api/upload        → распаковка zip, парсинг manifest, проверки, запись в БД
 ├─ GET  /api/report/:id    → находки + severity
 ├─ GET  /api/play/:id      → статика курса + SCORM API wrapper
 ├─ POST /api/comments      → CRUD комментариев
 └─ POST /api/export        → генерация xlsx/pdf

PostgreSQL (docker)
 └─ users, packages, findings, comments, sessions

SCORM-плеер (ядро, наибольший риск)
 └─ iframe с курсом + эмуляция SCORM 2004 RTE (Initialize/Terminate/
    GetValue/SetValue/Commit), перехват ошибок, лог вызовов → находки
```

Ключевой компонент — эмулятор SCORM 2004 RTE (мини-LMS в браузере): это и «тестирование+отладка», и главный технический риск.

## Фазы

- **Фаза 0 — каркас**: Next.js-скелет, Postgres в docker, CI (lint+build), локальный запуск.
- **Фаза 1 — приёмка (MVP)**: загрузка zip, парсер imsmanifest.xml, движок структурных проверок, отчёт.
- **Фаза 2 — плеер**: SCORM 2004 RTE-эмулятор, лог вызовов → находки.
- **Фаза 3 — рецензирование**: поэкранные комментарии, экспорт xlsx/pdf.
- **Фаза 4 — аккаунты и публикация**: auth, docker-compose для VPS.
